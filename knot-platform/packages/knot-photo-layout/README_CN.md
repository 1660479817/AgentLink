# @knot/photo-layout

一组图片怎么排：先按真实宽高切成若干等高行，再给每行定一个高度。

卡片（`web/src/components/PhotoGallery.vue`）和分享图（`backend/src/sharePoster.js`）共用 `planPhotoRows`，
普通比例的一组图在两处切法一致。只有预算不同，且两份预算都定义在这里——卡片用 `LAYOUT_RULES`，
分享图用 `POSTER_LAYOUT_RULES`，调用方不再各留一份副本。卡片单行封顶 200% 内容宽（1:2 以内的手机截图整张放得下），
且不留按不住的窄格；分享图单行放到 300%、整块拼图另有上限，也不需要考虑点击。极端比例混排时，
这两种取舍可能选出不同的切法；海报里「一张图最高多高」只认它自己的 300%，单图与拼图同源。

盒子形状按 1:4–8:1 夹取，但裁切量始终按图片真实比例算：1:8 的长截图不会被当成 1:4，
10:1 的全景也不会被记成「没裁」。极端图与普通图也不会被硬塞进一行，把某一格挤到 44px 以下：
这条优先于代价函数。

- `photoAspect(photo)`：一张图的真实宽高比，缺尺寸时按 4:3。不夹取。
- `planPhotoRows(aspects, rules)`：穷举切分（`2^(n-1)` 种），返回每行的行高、每格份额与裁切方向。
- `planPhotoLayout(photos)`：卡片用，切行结果直接给 CSS 变量。
- `planPhotoBoxes(photos, { width, gap, rules })`：分享图用，把行高乘成像素框，交给 sharp 裁图贴图。
- `LAYOUT_RULES`：目标行高、行高上下限、整组高度上限、最窄格（软目标与 44px 硬底线）、裁切罚分。调整排版口味只改这里。
- `POSTER_LAYOUT_RULES`：同一份规则、换成分享图的预算——单行行高放到 300% 内容宽，整块拼图放到 400%，`maxCard` 打开 `strictCard` 作为硬上限，拼图再怎么排也不会把图撑过高度限制。可点底线在这里关闭（`minTapShare: 0`）：海报不是用来点的，而把每张极端图都拆成一行，会让极端拼图高出好几倍内容宽。普通比例的相册在两处排法一致。
- `LAYOUT_VERSION`：规则一改就在规则旁边抬一档。分享图的缓存键带着它，已生成的图会按新排法重画，而不是继续发旧图。

设计说明写在 `src/index.js` 开头：为什么不用量 DOM、为什么「太高的图」不需要特判、代价函数各罚什么。
