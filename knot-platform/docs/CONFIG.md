# Knot configuration

This document is generated by `packages/knot-config/src/schema.mjs`; do not hand-edit. To change a configuration item, change the schema, then run:

```bash
node ops/scripts/config.mjs template --write           # sites/_template/site.env
node ops/scripts/config.mjs platform-template --write  # sites/_template/platform.env
node ops/scripts/config.mjs xknot-template --write     # sites/_template/xknot.env
node ops/scripts/config.mjs entry-template --write      # sites/_template/entry.example.env
node ops/scripts/config.mjs docs --write               # regenerate this document
```

## Official deployment methods

By public-facing shape, there are two: **local only** (leave `KNOT_DOMAIN=` empty, `KNOT_ENTRY_ENABLED=0`, bind loopback only) and
**xknot.si sub-subdomain** (`KNOT_DOMAIN=<label>.xknot.si`, via the back-origin tunnel). Both hold whether the instance host is this machine or another machine:
when the dev machine takes a subdomain, `KNOT_ENTRY_ENABLED` can be `0` — the hub wires the entry automatically; this machine only runs the tunnel and the content.
Standalone domains, intranet exposure, and a fixed public IP direct connection are all outside the official scope and count as user customization.

## Three boundaries

| Boundary | Location | Holds what | Can enter the repo |
| --- | --- | --- | --- |
| Code | `backend/` `web/` `packages/` | the real default behavior | yes |
| Deployment | `ops/` | scripts, templates, LaunchAgent, systemd unit. No site values | yes |
| Config | `sites/<site>/` | site profile, topology, secrets | no (except `sites/_template/`) |

Environment variables only override defaults in code. A key is either registered in `packages/knot-config/src/schema.mjs`, or it isn't read.
On startup the Backend validates the environment against the same registry: illegal values exit immediately, missing required items disable admin features; files are strictly validated for unknown keys before deployment.

One directory per site:

| File | Holds what | Written by |
| --- | --- | --- |
| `sites/<site>/site.env` | domain, host, port, path, entry, tunnel. No passwords | ops |
| `sites/<site>/profile.json` | self-description zone: name, default locale, one-line intro, long intro, logo, owner, contact, region, timezone, tags (ten flat fields). Not in the repo | the owner, edited in the XKnot section of `/admin` |
| `sites/<site>/platform.env` | SMTP password, initial prices, admin token. Mode 600 | deploy script |
| `sites/<site>/xknot.env` | instance id, hub origin, issue date and delegated-mailing credentials. Mode 600 | issued by the hub, written by `join-xknot.sh` |
| `sites/<site>/tunnel.env` | the back-origin tunnel's account, private-key filename, and local/entry ports (the `KNOT_TUNNEL` group). Mode 600 | written when the XKnot section of `/admin` auto-wires the tunnel |
| `sites/<site>/entry.<label>.xknot.si.env` | the entry for an xknot.si subdomain: domain, static root, conf, cert. One per site | ops |
| `sites/<site>/agents/` | Internal Personal Agent auth codes, mode 700 | scripts |

**Deployment and federation are two independent lines.** `deploy-site.sh` only reads `site.env` and `platform.env`;
`xknot.env` is only handed to the Backend at runtime — without it the site still deploys and runs, just not federated.
Conversely, redeploying, switching machines, or rolling back never touches the federation credentials.

## Site configuration (`sites/<site>/site.env`)

### Site

| Variable | Default | Required | Description |
| --- | --- | --- | --- |
| `KNOT_PUBLIC_ORIGIN` | `http://127.0.0.1:8080` |  | Public-facing address. Local only: write http://127.0.0.1:<KNOT_PORT>; after taking an xknot.si subdomain, write the hub-issued https://<label>.xknot.si. |
| `KNOT_DOMAIN` | (empty) |  | The sub-subdomain issued by xknot.si, shaped <label>.xknot.si. Leave empty for local-only access; when taking a subdomain, match the entry filename. |
| `KNOT_HUB_ORIGIN` | `https://xknot.si` |  | Which hub the first join submits the application to. Defaults to the federation entry xknot.si; local integration can point at a dev hub. |
| `KNOT_PORT` | `8080` |  | The port the Backend listens on, on the instance host. |
| `KNOT_BIND_HOST` | `127.0.0.1` |  | The address the Backend binds. Local and entry back-origin both go only local, keep 127.0.0.1; to let machines on the same LAN open the admin console /admin, set it to 0.0.0.0. When bound to loopback, the admin console link generated on the "Mine" page always starts with 127.0.0.1 and won't open when copied to another device; the deploy script warns once when it's public-facing by domain yet loopback-bound. |
| `KNOT_SESSION_COOKIE_NAME` | `knot_sid` |  | The session cookie name. Must differ when several sites run under one domain. |
| `KNOT_ADMIN_EMAIL` | (empty) | Yes | The site admin email. Required; logging in with this email grants platform admin rights; suggestions and complaints also arrive here. |
| `KNOT_SESSION_TTL_DAYS` | `30` |  | Login session lifetime (days). The cookie and sessions.expires_at use the same value. |

### Instance host

| Variable | Default | Required | Description |
| --- | --- | --- | --- |
| `KNOT_DB_MODE` | `local` |  | local uses the machine's Homebrew Postgres; external uses KNOT_DATABASE_URL and doesn't start a local database. |
| `KNOT_DATABASE_URL` | (empty) |  | The connection string when KNOT_DB_MODE=external. May contain a password; treat as a secret. |
| `KNOT_PGPORT` | `5433` |  | The local Postgres port, offset from the system default 5432. |
| `KNOT_PGDATA` | `$HOME/knot/pgdata` |  | The local Postgres data directory. |
| `KNOT_PGLOG` | `$HOME/knot/pg.log` |  | The local Postgres log file. |
| `KNOT_PG_BIN` | `/opt/homebrew/opt/postgresql@16/bin` |  | The bin directory of PostgreSQL 16. Apple Silicon Homebrew is /opt/homebrew; Intel changes it to /usr/local/opt/postgresql@16/bin. |
| `KNOT_UPLOAD_DIR` | see note |  | The upload directory. Empty uses <deploy root>/var/uploads; put it outside the release package so upgrades and rollbacks never touch it. |
| `KNOT_BACKUP_DIR` | (empty) |  | The backup directory. Empty means undecided (public sites get reminded); write `null` to mean explicitly no backup, no more reminders; both leave the backup task uninstalled. Filling a directory makes deploy-site.sh install the daily 04:15 backup task (launchd or systemd timer). |
| `KNOT_BACKUP_KEEP` | `7` |  | How many recent backups to keep. |
| `KNOT_BACKUP_SITES` | `1` |  | 1 means the backup also collects sites/<site>/: platform.env (SMTP password, admin token), agents/ (agent credentials). Backing up only the database loses email login and agents when switching machines. |
| `KNOT_BACKUP_OPENCLAW` | `auto` |  | Backing up the OpenClaw state directory. auto collects it when $HOME/.openclaw exists; 1 must collect; 0 skip. Only collects config, credentials, and agent workspaces, not cache/browser/npm. |
| `KNOT_OPENCLAW` | `auto` |  | auto syncs only when openclaw is installed; 1 must sync; 0 skip. |
| `KNOT_SYSTEMD_DIR` | `/etc/systemd/system` |  | Where systemd units install on a Linux instance host. |
| `KNOT_SERVICE_USER` | `knot` |  | The system account running the Knot Backend on a Linux instance host. Needs permissions on the directories it reads. |

### Publish from the dev machine

| Variable | Default | Required | Description |
| --- | --- | --- | --- |
| `KNOT_DEPLOY_SSH` | (empty) |  | The instance host's ssh target, shaped user@host. Empty means the target is this machine, run deploy-site.sh in place. |
| `KNOT_DEPLOY_DIR` | see note |  | The deploy root on the instance host. sites/, releases/, current, var/ all live here; code is under releases/<version>. Empty derives ~/knot/<site> from the site name; one deploy root holds only one site, don't share it with the source repo or another site's directory. |
| `KNOT_DEPLOY_SSH_KEY` | (empty) |  | The private key for publishing. Empty uses the ssh default identity. |
| `KNOT_DEPLOY_VERIFY_URL` | see note |  | The health-check address after deployment. Empty derives from http://<instance host>:<KNOT_PORT>/api/health. |
| `KNOT_DEPLOY_KEEP` | `5` |  | How many historical release packages to keep on the instance host. The current version and the rollback target are always kept; the rest are cleared by time. |
| `KNOT_ARTIFACT_DIR` | see note |  | The output directory on the dev machine for build artifacts (release package and checksum). Empty uses <knot-platform>/artifacts. |

### Public entry

| Variable | Default | Required | Description |
| --- | --- | --- | --- |
| `KNOT_ENTRY_ENABLED` | `0` |  | 1 means this machine pushes the WebUI and nginx config to KNOT_ENTRY_SSH at deploy time; 0 means don't touch the entry host (local only, or the hub has already auto-wired the entry). |
| `KNOT_ENTRY_SSH` | (empty) |  | The entry host's ssh target. |
| `KNOT_ENTRY_SSH_KEY` | (empty) |  | The private key for pushing pages from the dev machine. Empty uses the ssh default identity or ssh-agent; the entry host usually rejects id_rsa, use a dedicated deploy key, e.g. $HOME/.ssh/<dedicated deploy key>. |
| `KNOT_ENTRY_PUSH_KEY` | `$HOME/.ssh/knot-entry-publish` |  | The private key for pushing the public snapshot from the instance host; can differ from KNOT_ENTRY_SSH_KEY. |
| `KNOT_ENTRY_WEB_ROOT` | `/var/www/knot` |  | The directory holding the WebUI on the entry host. Must be written per subdomain: empty falls back to the shared /var/www/knot and overwrites other subdomains on the same machine. |
| `KNOT_ENTRY_CONF` | `/etc/nginx/conf.d/knot.conf` |  | The nginx site config path on the entry host. Must be written per subdomain: empty falls back to the shared /etc/nginx/conf.d/knot.conf. |
| `KNOT_ENTRY_WEB_OWNER` | `nginx:nginx` |  | The owner of the WebUI directory. |
| `KNOT_ENTRY_CACHE_DIR` | `/var/cache/nginx/knot_uploads` |  | The reverse-proxy cache directory for uploaded files. |
| `KNOT_ENTRY_CACHE_ZONE` | `knot_uploads` |  | The nginx proxy_cache zone name. |
| `KNOT_ENTRY_CACHE_SIZE` | `2g` |  | The cache cap, in nginx syntax, e.g. 2g. |
| `KNOT_ENTRY_MAX_BODY` | `52m` |  | The request-body cap the entry host accepts. Must exceed the backend attachment cap, or large files get truncated at nginx. |
| `KNOT_ENTRY_ACCESS_LOG` | `/var/log/nginx/knot-access.log` |  | The entry access log. Subdomains on the same entry host share one file, split by $host; the hub's traffic aggregation reads it. |
| `KNOT_ENTRY_PROXY_PORT` | `18080` |  | The entry back-origin port. nginx forwards /api here, and the tunnel forwards it back to the instance host. |
| `KNOT_ENTRY_SSL` | `1` |  | 1 listens on 443 and configures the certificate; 0 listens on 80 only, used when the certificate isn't signed yet. |
| `KNOT_ENTRY_CERT` | see note |  | The certificate chain. Empty derives from KNOT_DOMAIN. |
| `KNOT_ENTRY_KEY` | see note |  | The certificate private key. Empty derives from KNOT_DOMAIN. |
| `KNOT_ENTRY_RELOAD_CMD` | `sudo systemctl reload nginx` |  | The reload command after changing the nginx config. Non-systemd machines change it to their own. |

### Back-origin tunnel

| Variable | Default | Required | Description |
| --- | --- | --- | --- |
| `KNOT_TUNNEL` | `0` |  | 1 means the instance host dials out to build the tunnel, so the xknot.si subdomain entry can reach back. Leave 0 with no entry; when local also takes a subdomain, sites/<site>/tunnel.env writes 1. |
| `KNOT_TUNNEL_SSH` | see note |  | The tunnel account. Empty is knot-tunnel@<KNOT_ENTRY_SSH's host>. |
| `KNOT_TUNNEL_KEY` | `$HOME/.ssh/knot-entry` |  | The private key for building the tunnel on the instance host. Relative paths resolve from the site directory (sites/<site>/); the auto-wired tunnel.env uses tunnel_ed25519. |
| `KNOT_TUNNEL_LOCAL_PORT` | see note |  | The port the tunnel lands on locally. Empty equals KNOT_PORT. |
| `KNOT_TUNNEL_REMOTE_PORT` | see note |  | The port the tunnel occupies on the entry host. Empty equals KNOT_ENTRY_PROXY_PORT. |

## XKnot federation configuration (`sites/<site>/xknot.env`)

Only holds what the hub issued; it takes no part in deployment derivation. The file may not exist.

Key names and semantics are the federation contract, see `xknot.si/docs/FEDERATION.md` §7.4; the `xknot.env` filename and location
are this implementation's convention — another implementation only needs to read these same keys.

```bash
./ops/scripts/join-xknot.sh --payload ~/xknot-access.env   # write and validate
./ops/scripts/join-xknot.sh --status                       # view current federation status
node ops/scripts/config.mjs check --xknot --site <site>    # validate only this file
```

| Variable | Default | Required | Description |
| --- | --- | --- | --- |
| `XKNOT_INSTANCE_ID` | (empty) | Yes | The instance id in the hub roster (lowercase letters, digits, hyphens). Written into /api/health's instance, for the hub to verify identity. |
| `XKNOT_HUB_ORIGIN` | `https://xknot.si` |  | The hub origin this instance joins. The delegated-mailing address derives from it. |
| `XKNOT_HUB_RELAY_URL` | (empty) |  | The full delegated-mailing address. Empty derives from XKNOT_HUB_ORIGIN; only hand-written when switching entries. |
| `XKNOT_HUB_RELAY_TOKEN` | (empty) |  | The delegated-mailing credential issued by the hub. Exists only in xknot.env; never enters mail, the repo, or the release package. |
| `XKNOT_ISSUED_URL` | (empty) |  | The public address issued by the hub. Part of the issued zone, consistent with the roster's url; the node only reads it. |
| `XKNOT_ISSUED_AT` | (empty) |  | The issue date (YYYY-MM-DD). Part of the issued zone, reported outward as since. |
| `XKNOT_TIER` | (empty) |  | The tier issued by the hub: free or paid (early demo / partner / community still readable). Part of the issued zone; empty means not reported outward. |
| `XKNOT_STATUS` | (empty) |  | The status issued by the hub. Part of the issued zone; empty means not reported outward. |

## Validation

Before deployment it runs `node ops/scripts/config.mjs check`; on any problem it stops immediately, never deploying halfway.
Manual checks:

```bash
node ops/scripts/config.mjs check --site <site>              # check site.env
node ops/scripts/config.mjs check --platform --site <site>   # check the instance host's platform.env
node ops/scripts/config.mjs check --xknot --site <site>      # check the federation xknot.env
node ops/scripts/config.mjs sites                            # list existing sites
```

Required and cross-key rules:

| Rule | Condition |
| --- | --- |
| KNOT_ENTRY_ENABLED=1 requires KNOT_ENTRY_SSH. When not pushing the entry yourself, write KNOT_ENTRY_ENABLED=0. | `KNOT_ENTRY_ENABLED=1` |
| KNOT_DB_MODE=external requires KNOT_DATABASE_URL. | `KNOT_DB_MODE=external` |
| When taking a subdomain, write KNOT_PUBLIC_ORIGIN=https://<label>.xknot.si and the hostname must match KNOT_DOMAIN. | `KNOT_DOMAIN` non-empty |
| When pushing the entry yourself (`KNOT_ENTRY_ENABLED=1`), set KNOT_TUNNEL=1; when the hub auto-wires the entry, the tunnel is written in `tunnel.env`, not required here. | `KNOT_DOMAIN` non-empty |
| Without a subdomain, KNOT_PUBLIC_ORIGIN only accepts a loopback address, and no tunnel is built. | `KNOT_DOMAIN` empty |
