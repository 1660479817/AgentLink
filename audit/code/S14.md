| S14-01 | P0 | `uploadStore.js:150-152`；`routes/web.js:167-175`、`385-399`、`506-507` | 安全（存储型 XSS） | 非图片上传（`kind` 为 audio/file）既不做内容校验，也不归一 MIME：客户端 multipart 里的 `Content-Type` 原样入库。`/api/web/audio` 的过滤器按**扩展名**放行（`isAudioUpload`），于是「文件名 `.mp3` + `Content-Type: text/html` + HTML 正文」能通过；`GET /api/web/uploads/:id` 用 `res.type(row.mime)` 内联回源。音频会写进 `intel_files`，公开帖上的音频被 `mediaAudience` 判为 `public`，任何访客/管理员打开该 URL 就在站点同源执行脚本（Cookie 是 HttpOnly，但可代受害者调接口、以管理员身份操作） | `} else if (!mime) { removeFile(...); throw uploadError("bad_mime"); }` 只判空；`return AUDIO_EXT.test(name)` 兜底认扩展名；`res.type(opened.row.mime); fs.createReadStream(opened.filePath).pipe(res);` | 按 `kind` 设 MIME 白名单并用魔数复核；非图片/音频一律 `Content-Disposition: attachment`，或把用户媒体放到独立源 | 高 |
| S14-02 | P2 | `videoPoster.js:9-42` | 安全（SSRF） | `publicUrl` 的私有地址判断只覆盖 `::1`、`fe80:`、`fc`、`fd`，漏掉 `::`、IPv4-mapped `::ffff:a.b.c.d`、NAT64 `64:ff9b::/96`、6to4 `2002::/16`；且先 `lookup()` 校验、再由 `fetch()` 二次解析，存在 DNS rebinding 窗口。结合 `resolveVideo` 的落地页解析，后端会被引去抓内网地址。同一函数还有死分支：`URL.hostname` 对 IPv6 字面量保留方括号，`net.isIP("[::1]")` 返回 0，所有 IPv6 直链都走 DNS 查询失败被拒（注释声称处理了 IPv6） | `return ip === "::1" \|\| ip.startsWith("fe80:") \|\| ip.startsWith("fc") \|\| ip.startsWith("fd");`；校验后 `const response = await fetch(url, ...)` 重新解析 | 用 `net.BlockList` 统一判 IPv4/IPv6 并先剥方括号；连接阶段复用已解析 IP（自定义 lookup/dispatcher），补 `::`、NAT64、6to4 | 中 |
| S14-03 | P2 | `videoPoster.js:88-111` | 资源 | `readHtml` 先把整个响应体读进内存再截断，没有 `Content-Length` 或流式上限；重定向分支与 `!response.ok` 分支都不 `cancel()` 响应体，连接不复用；每跳 4 秒、最多 4 跳，发布路径最长阻塞约 16 秒。同一条视频 URL 在 `resolveVideo` 与 `assertReachable`（`links.js:79`）各抓一次 | `const bytes = Buffer.from(await response.arrayBuffer()).subarray(0, HTML_LIMIT);`；`if (!response.ok) return { url, html: "" };`（无 cancel） | 边读边累计到上限即 abort；所有分支 `response.body?.cancel?.()`；一次发布内复用解析结果 | 高 |
| S14-04 | P2 | `uploadStore.js:155-163`；`107-118` | 数据一致性 | 配额是「先查后写」：`SELECT sum(size)` 与 `INSERT` 不在一个事务里，也没有锁或约束。同一钱包并发 N 个上传各读到同一 `used`，全部通过，实际用量可超上限 N 倍；Agent 与主人共用额度时同样成立 | `const used = await userUploadBytes(pool, userId); if (used + bytes > limit) ...`，随后才 `INSERT INTO uploads` | 同钱包取 `pg_advisory_xact_lock` 后在事务里查+写；或用计数列做 `UPDATE ... WHERE used + $n <= limit` 的条件更新 | 高 |
| S14-05 | P2 | `uploads.js:147-195` | 数据一致性 | `acceptAvatar` 原地改写既有 `uploads` 行（`storage_name`、`mime`、`size`、`sha256`、`width`、`height`）并删除旧文件，但不检查该行是否已被帖子引用。把一张旧帖图设为头像，会让那条帖子的图片变成 512×512 裁图，原件不可恢复；`uploads.sha256/size` 与 `intel.content_hash` 从此对不上，审计与去重口径失真 | 先按 id 取行（只限 `account_id`），随后 `UPDATE uploads SET storage_name = $1, mime = 'image/jpeg', size = $2, sha256 = $3 ...`，并 `fs.rmSync(readableBlobPath(uploadDir, row.storage_name))` | 头像转换产物另建一行（新 upload id），`accounts.avatar_upload_id` 指向新行；被引用过的行不可变 | 高 |
| S14-06 | P3 | `uploadStore.js:210`；`routes/web.js:450-467` | 契约/功能 | 所有 `kind` 都返回 `/api/web/uploads/{id}`。附件的 `original_name` 命中 `isAttachmentUpload` 时 `readableUpload` 直接返回 null，所以 `/api/web/files` 与 `/api/agent/uploads` 给附件返回的 `url` 恒为 404，而文档把它写成正常返回字段 | `return { id, url: publicUploadUrl(id), name: ... }`；`if (isAttachmentUpload({ originalname: row.original_name \|\| row.storage_name })) return null;` | 附件不返回 `url`（返回 null 或下载端点说明），文档同步 | 高 |
| S14-07 | P3 | `wish.js:20-27`；`discoverBoard.js:260-268` | 数据一致性/契约 | `wishLive` 为旧行兜底 `created_at + 24h`，但公开快照的到期扫描只匹配 `expires_at` 非空的行。`expires_at IS NULL` 的 wish 到期不会触发快照重写，会留在 `discover.json` 直到别的内容变动，与文档「到期后一分钟内重写」不符。另外注释写「018 迁移前」，本仓库只有 `001_accounts.sql`，`intel.expires_at` 本就在基线里 | `COALESCE(${alias}.expires_at, ${alias}.created_at + interval '24 hours')` 对比 `WHERE kind = 'wish' AND expires_at > $1 AND expires_at <= $2` | 扫描条件改用同一个 deadline 表达式；注释不引用不存在的迁移编号 | 中 |
| S14-08 | P3 | `xknotJoin.js:60-90` | 正确性 | `applicationPayload` 先把 `email` 截到 120 码点，`missingFields` 再对截断后的值跑正则。超长邮箱会被截成一个「看起来合法」的地址交给中枢，申请里的联系方式是错的，本地也不报错 | `email: cut(email \|\| site.contact, 120)`；`if (!EMAIL_RE.test(payload.email)) missing.push("email")` | 先按原始值校验（含长度上限），超长直接 `incomplete`，不要静默截断 | 高 |
| S14-09 | P2 | `uploads.test.js:12-41`；`uploadStore.test.js:126-149`；`wish.test.js:27-32`；`videoPoster.js`（无测试文件） | 测试缺口 | 高风险路径没有断言：非图片上传的 MIME 是否归一（S14-01 那条路径零覆盖）；`acceptAvatar` 只测 happy path，没有「不是本人上传」「该 upload 已被帖子引用」；`wishLive` 只对 SQL 字符串做正则，不验证 NULL 兜底与到期边界；`readHtml`/`resolveVideo` 的重定向、超大响应、失败分支没有任何测试 | `assert.equal(avatarBufferError(png(512, 512)), null)`（`png()` 是 24 字节伪造头）；`assert.match(sql, /i\.created_at \+ interval '24 hours'/)` | 补 `text/html` 冒充音频应被拒、`acceptAvatar` 所有权与引用态、wish 到期 SQL 行为、抓取上限的用例 | 高 |

| 位置 | 声称 | 实际 | 依据 |
|---|---|---|---|
