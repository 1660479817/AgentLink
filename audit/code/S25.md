# S25 — xknot.si/admin 控制台脚本

## 已读清单

| 文件 | 行数 | 结论 |
|---|---|---|
| xknot.si/admin/admin.js | 1214 | 13 issues |

无构建步骤的单文件控制台：自写 `el()` 造 DOM，全部文本走 `textContent`／文本节点。**XSS 结论：不存在存储型 XSS**。逐个汇点：

- `el()` 的 `html` 分支 `node.innerHTML = value`（`admin.js:151`）是唯一 HTML 解析入口，全文件无任何调用点传 `html`，是死通道。
- 所有第三方字段（`item.name`／`operator`／`intro`／`tags`／`email`／`publicKey`／`row.name`／`config.note`／`event.ref`／`error.data.fields`）都作为 `el()` 的 text 子节点或 `text` 属性进入，`document.createTextNode(String(child))` 转义。
- 动态属性只有 `href`（`:288`、`:1050`、`:1054`）与固定 `src`／`srcset`（`:694-696`）。`href` 值当前全部由服务端派生：申请地址来自 `store.mjs:343` 的 `subdomainUrl(subdomain)`，清单地址来自 `instances.json`（写入前过 `profile-schema.mjs:223` 的 `isHttpsUrl`），`mailto:` 前缀固定。`setAttribute` 不做 HTML 解析，无法逃出属性。
- 页面 CSP 为 `script-src 'self'`（`server/app.mjs:781`），`javascript:` 导航同样被拦。两道都是「当前不可利用」，但见 S25-11。
