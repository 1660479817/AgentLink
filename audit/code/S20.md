补充事实（用于判断一致性，不单独计为发现）：

- 三份由 schema 生成的模板与生成器输出**逐字节相同**：`renderSiteExample()` / `renderPlatformExample()` / `renderJoinExample()` 的输出分别与 `site.env`、`platform.env`、`xknot.env` 比对无差异。键集、顺序、默认值、注释文案全部对得上（`site` 50 键 / `platform` 53 键去 computed / `xknot` 8 键）。
- 审的是工作区版本。`git diff` 显示 `site.env:126` 相对 HEAD 多了一句「相对路径按站点目录解析」——这是 `schema.mjs:502` 的新描述已经重生成但未提交，不是另一份事实来源；提交态的旧句会在下次提交时自然消失。
- `entry.example.env` 不在生成链里，但它的 6 个键全部已登记：5 个 `SITE_KEYS` + 1 个 `ENTRY_KEYS.KNOT_ENTRY_SERVE`；`ENTRY_KEYS` 唯一登记项也出现在文件里。键差异 = **0（缺 0 / 多 0 / 改名 0 / 默认值不符 0）**。
- 敏感项默认全部为空或以 `#` 注释（`SMTP_PASS`、`SMTP_USER`、`SMTP_FROM`、`MAIL_FROM`、`KNOT_DATABASE_URL`、`KNOT_ADMIN_TOKEN`、`KNOT_ADMIN_ORIGIN`、`KNOT_COUPON_FACE`、`KNOT_XKNOT_HUB_RELAY_TOKEN`、`XKNOT_INSTANCE_ID` 等），没有令牌、密码、真实域名残留。`KNOT_BIND_HOST` 默认回环、`KNOT_ENTRY_ENABLED`/`KNOT_TUNNEL` 默认 0、`KNOT_ENTRY_SSL` 默认 1，开关方向都安全。
- `platform.env` 头部「只在文件里还没有时写入初值」与 `ops/scripts/config.mjs:407`（`if (Object.hasOwn(existing, entry.key)) continue`）一致，不是空话。
- `KNOT_BACKUP_DIR` 的「留空/写 `null` 都不装备份、`null` 不再提醒」与 `backup-knot.sh:40-42`、`checkSite` 的 `backup-off` warning、`backup-knot.test.mjs:165` 一致，也不会建出名为 `null` 的目录。
- `KNOT_ADMIN_ORIGIN`「留空按绑定地址与网卡推断」与 `backend/src/adminHosts.js:58-62` 一致。
