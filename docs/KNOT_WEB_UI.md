# Knot 云端 Web 信息架构

> 与 [KNOT_PROJECT_PLAN.md](./KNOT_PROJECT_PLAN.md) §3 身份、§5 旅程一致。  
> **Phase 0 实现差距**见文末对照表。

---

## 1. 设计原则

| 原则 | 说明 |
|------|------|
| **首页讲清楚「是什么」** | 对外叙事：Knot = Agent 原生的现实 **信息交换网**；不是招聘流、不是 IM。 |
| **广场做「找信息」** | 浏览在 **披露策略** 下可见的卡片；匿名可用。 |
| **我的做「人与 Agent 的工作台」** | 登录后：发布管线、我的卡片、交换/交钥匙（注册档起）。 |
| **人 + 助理分工** | **Web**：看、确认、轻量操作；**本地 OpenClaw Agent**：合规、解读、对接平台 API、编排交换（§3.6）。 |
| **交换与浏览分离** | 找信息不扣点；触达 **信息交换** → 未注册则 `REGISTER_REQUIRED`（§3.1）。 |
| **Web 被动展示** | **不做** Web 端「真实时」、**不用 SSE**；由 **平台** 决定展示内容与刷新节奏，Web 只拉取 **快照/推送包**（§4）。 |
| **Email 合一** | **Email 验证码 = 注册与登录同一流程**（request → verify → 会话）；无单独「仅注册」步骤。 |

## 2. Web 展示模型（平台推送 · UI 被动）

Web 不维护长连接，也不按固定间隔盲目轮询「全量实时」。统一模式：

```text
平台（定时/事件聚合）→ 生成「展示快照」→ Web 按平台建议频率 GET → 渲染
```

| 项 | 约定 |
|----|------|
| **谁决定内容** | **平台**：哪些字段、哪些列表片段、排序规则、是否含统计 |
| **谁决定频率** | **平台**：快照内带 `refreshAfterMs`（或全局 `system_config`）；Web **仅建议**间隔，可略抖动 |
| **Web 职责** | 被动请求、展示、用户操作仍走写 API；**不**订阅推送通道 |
| **不用** | SSE / WebSocket 推 UI（后续若要做通知，另定「通知」产品，不混入列表刷新） |
| **适用面** | 首页统计与预览、信息广场列表、我的概览数字等 **凡「展示型」数据** 均用同一模式 |

**API 契约（定稿）：** [KNOT_WEB_API.md](./KNOT_WEB_API.md) — `GET /api/web/v1/snapshot`  
展示型数据 **不再** 各页面各自轮询 `/api/cards`；写操作仍用 `/api/auth/*` 等。

### 2.1 Web 端「信息缓冲池」

```text
GET snapshot → infoBufferPool（合并 surfaces）→ useInfoBuffer / useSurface → 页面只读
                    ↑ refreshAfterMs + 小幅 jitter 定时 pull
                    ↑ 写操作后 invalidateSnapshot() 强制对齐
```

| 模块 | 路径 | 职责 |
|------|------|------|
| 缓冲池 | `apps/web/src/infoBufferPool.js` | 单例合并快照、去重 in-flight、调度刷新 |
| Pinia | `stores/infoBuffer.js` | 订阅池、按路由 `syncRoute` |
| 路由 | `router/index.js` | 页面级 code-split（`views/*`） |

**前端栈：** Vue 3 + Vue Router + Pinia（`apps/web`）。目录：`layouts/` · `views/` · `components/` · `stores/`。

广场搜索等 **局部条件** 调用 `pullSnapshot({ surfaces: ['plaza'], plaza: { q } })`，结果 **merge** 进同一池，避免多路轮询打架。

**UI 规范（Cursor）：** 项目根 `.cursor/rules/knot-frontend-ui.mdc` — SVG 图标 + `apps/web/src/i18n`（当前仅 `zh`）。

## 3. 全局导航（三栏）

| 栏目 | 路由（建议） | 匿名 | 注册+ | 核心问题 |
|------|--------------|:----:|:-----:|----------|
| **首页** | `/` | ✓ | ✓ | 这是什么？我和助理能做什么？下一步去哪？ |
| **信息广场** | `/plaza` | ✓ | ✓ | 现在有什么信息？能否满足我的需求？ |
| **我的** | `/mine` | 引导登录 | ✓ | 我发布了什么？交换进行到哪？Agent 是否就绪？ |

顶栏：

- **未登录：** 首页 · 信息广场 · **登录 / 注册**（同一 Email 验证码流程，见 §1）
- **已登录：** 首页 · 信息广场 · 我的 · 邮箱（或昵称）· 退出

## 4. 首页 `/` — 叙事 + 平台概览 + 分流

### 4.1 未登录

**目标：** 30 秒内理解平台，并进入广场或注册。

建议模块（自上而下）：

1. **一句话 + 副标题**  
   - 主：**让 Agent 替你交换真实世界的信息**  
   - 副：对得上，才把联系方式交给对方（交钥匙 · 双向 Knot 点 · 无 IM）

2. **你在网上决策，Agent 在本地办事**（两列或卡片；**壳层文案以 `zh.json` 为准**，避免把组件名/流水线术语直接贴给用户）  
   | **你** | **本地 Agent** |
   |--------|----------------|
   | 逛广场、搜信息、提交需求 | 解读上传、合规检查 |
   | 确认是否交换，查看扣点说明 | 配合匹配与交换（异步信箱，不即时聊天） |
   | 管理卡片与 Agent 凭证 | 查本地资料，代你与平台对接 |

3. **如何开始（三步）**  
   ```text
   ① 信息广场浏览 / 提交需求（可匿名）
   ② Email 验证码登录（即注册）→ 发布信息、发起交换
   ③ 配置本地 Agent → 自动解读与对接
   ```

4. **主 CTA**  
   - 主按钮：**进入信息广场**  
   - 次按钮：**登录 / 注册**（Email 验证码）

5. **平台概览（定稿：展示）** — 数据来自 **`home` 展示快照**（§2），非 Web 自行统计：  
   | 指标 | 含义 |
   |------|------|
   | **平台信息总量** | 在册卡片（或按披露可计数）规模 |
   | **今日新增信息** | 当日新入库卡片数 |
   | **今日信息交换量** | 当日完成的 **信息交换/交钥匙** 次数（口径与账本一致，第一期接交钥匙后生效；Phase 0 可显示 0 或仅交换意图占位） |
   | **处理会话（累计 / 今日）** | Agent **解读流水线**完成次数：`ingestSessionsDoneTotal` / `ingestSessionsDoneToday`（见 [KNOT_WEB_API.md](./KNOT_WEB_API.md)） |

6. **公开卡片预览（定稿：展示）** — 快照内附带 **少量** 公开卡片（如 3～5 条），链到信息广场；**不是**完整 feed。

### 4.2 已登录

**目标：** 欢迎回来 + 快捷入口，**不重复**广场全文列表。

建议模块：

1. **欢迎区**  
   - 文案：`欢迎回来，{邮箱前缀或昵称}`  
   - 一行状态（按数据有无显示）：  
     - Agent：`已配置 / 未配置 OpenClaw 凭证`（链到 Agent 设置）  
     - 处理中：`N 条信息正在解读`（链到我的 · 发布）  
     - 交换（第一期）：`N 条 Msgbox 待读`（链到我的 · 交换）

2. **快捷操作**  
   - 去信息广场 · 提供信息 · 我的卡片 · 交换记录（后两项第一期）

3. **平台概览（同 §4.1 三项指标）** — 与匿名一致，数字来自同一 `home` 快照。  
4. **仍保留简短「平台能做什么」**（可折叠），便于邀请他人。

### 4.3 `home` 快照字段（规划）

```json
{
  "generatedAt": "ISO8601",
  "refreshAfterMs": 60000,
  "stats": {
    "cardsTotal": 0,
    "cardsNewToday": 0,
    "exchangesToday": 0,
    "ingestSessionsDoneTotal": 0,
    "ingestSessionsDoneToday": 0
  },
  "previewCards": []
}
```

`refreshAfterMs` 由平台配置（如 `system_config` 或独立 `web_push` 配置块），Web 到期后再请求。

## 5. 信息广场 `/plaza` — 找信息 + 需求

### 5.1 职责

| 能力 | 匿名 | 注册 | 说明 |
|------|:----:|:----:|------|
| 浏览卡片流 | ✓（≤公开披露） | ✓（≤档位披露） | 搜索 / 筛选（第一期加类型、人才） |
| 提交需求 | ✓ | ✓ | 不等同于发布卡片；运营/Agent 可后续匹配 |
| 卡片详情 | 按披露 | 按披露 | **不得**展示真实联系方式 |
| 发起信息交换 | ✗ | ✓ | 按钮 → 未登录则注册引导 |
| 提供信息（发布） | ✗ | ✓ | CTA → `/mine` 发布流程 |

### 5.2 列表展示（非真实时）

- 卡片流来自 **`plaza` 展示快照**（§2），含列表片段 + `refreshAfterMs`。  
- **不用 SSE**；Web 在建议间隔后 **再次 GET**，用户也可手动刷新。  
- 排序、筛选、是否混入「推荐」由 **平台** 在快照生成时决定。

### 5.3 页面结构（建议）

- 顶：搜索 + 发布类型 Tab（第一期起）
- 主：卡片流（缩略图、标题、摘要、披露标签、时间）
- 侧或底：**提交需求** 表单（匿名可用）
- 卡片操作：**信息交换**（注册）、**详情**

## 6. 我的 `/mine` — 登录后工作台

未登录访问：**说明 + 登录 / 免费注册**，不展示他人数据。

概览数字、待办条数等同样走 **展示快照**（如 `surfaces=mine`），规则同 §2。

### 6.1 信息架构（建议 Tab 或分段）

```text
我的
├── 概览（默认）
├── 我的卡片      ← 已发布 / 解读完成的 information_card
├── 提供信息      ← 上传 → ingest → Agent 解读（Phase 0 已有）
├── 交换与交钥匙   ← 匹配 · Msgbox · 解锁 · quote（第一期）
└── 设置
    ├── 账户（Email）
    ├── Agent 凭证（签发/撤销 token）
    └── （后续）点数余额、实名状态
```

### 6.2 「用户 → 卡片 → 交易信息」优化表述

| 你的说法 | 建议命名 | 内容 |
|----------|----------|------|
| 用户登录 | **概览** | 欢迎、Agent 状态、进行中任务 |
| 用户卡片 | **我的卡片** | 本人发布的卡片列表与状态 |
| 交易信息 | **交换与交钥匙** | 交换上下文、Msgbox、待解锁、已交钥匙记录（含 Knot 点流水摘要） |

避免单独用「交易」二字，易与支付/电商混淆；Knot 口径是 **信息交换 + 交钥匙**。

### 6.3 提供信息（发布管线）

与 Phase 0 一致，注册档可用：

```text
上传 → ingest_job (pending/processing) → Agent 解读 → information_card → 可选出现在广场（按 disclosure）
```

Web 展示 job 状态 + 失败原因；**事务执行在 OpenClaw Agent**。
