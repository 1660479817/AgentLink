# Knot WebUI

人使用的前端。它在 AgentLink 平台外面，访问平台里的 Knot Backend。

与 [KNOT_PROJECT_PLAN.md](./KNOT_PROJECT_PLAN.md) 的两扇门一致。和 Backend 的契约见 [KNOT_WEB_API.md](./KNOT_WEB_API.md)。设计核对见 [KNOT_WEB_UI_AUDIT.md](./KNOT_WEB_UI_AUDIT.md)。

---

## 1. 这个前端负责什么

人用邮箱和校验码登录（Phase 0 为匿名 person）。**邮件**仅用于鉴权验证码与 Agent 令牌相关投递，不做业务通知。

人提交**原始信息**：

- **文字**（可在文中附带 URL，Agent 自行 web fetch 补充上下文）
- **图片**（上传到平台，公域按原图展示）

并标明需求、供给或情报。除违规外都在公域展示，样子和提交时一样：只有文字就是文字卡片，只有图片就是图片卡片，图文都有就一起展示。高价值情报再标一个类别。**不展示发布者**。联络方式仍只在对接后给对方。

用户打开**首页**即可浏览同一条信息流；顶栏搜索在同一页用 `?q=` 过滤，结果仍回到这条信息流。

所有用户供需情报由 Agent **自动撮合**。撮合成功后在**消息**中给出回应；用户点 **对接** 即同意**扣除积分**，随后展示**双方原始信息**与**联络方式**。

**高价值情报**按评价分数（1～10）记入积分，这是平台购买库存。对接扣除的积分是撮合费。余额在「我的」里体现。

## 2. 页面

| 页面 | 路由 | 人在这里做什么 |
|------|------|----------------|
| **首页** | `/` | 浏览同一条信息流；搜索（`?q=`）；提交供需；发情报 |
| **通知** | `/notifications` | 轻量**提醒**：审核打回、情报入账、待对接等 |
| **消息** | `/messages` | **回应列表**：按提交分组，一条信息可有多条撮合回应；可发起对接 |
| **我的** | `/mine` | 积分余额、账号、Agent 授权入口 |
| **Agent 授权** | `/delegate` | 发放/收回 Personal Agent 凭证 |

顶栏：标识、搜索、**通知**（角标）、**消息**（角标）、我的。

---

## 3. 通知 vs 消息

| | 通知 | 消息 |
|---|------|------|
| **性质** | 提醒「该去看一眼」 | 可持续翻阅的**回应工作区** |
| **典型内容** | 审核打回、情报 +N 分、有新的待对接 | 某条需求下的寻源建议、配对成功摘要等 |
| **角标** | 顶栏铃铛（仅未读） | 顶栏消息（仅未读） |
| **已读** | **仍保留在列表**，可翻阅历史 | 已读回应仍可在消息列表中查看 |
| **打回修改** | 通知点开 → 跳转「我的信息」编辑 | 不替代提交管理 |
| **多条对接** | — | 对接一条 **不** 使其它候选失效；每条回应可独立对接 |

---

## 4. 首页（对照 Facebook）

| 区块 | 行为 |
|------|------|
| **Composer** | 发动态：文字（可含 URL）+ 上传图片 + 选需求/供给 |
| **发情报** | 横滑条只留发布入口。已公开的情报不放在这里 |
| **信息流** | 需求、供给、情报同一条，按时间从新到旧。有 `?q=` 时仍是这一条，只换成搜中的结果 |

---

## 5. 信息卡片（公域）

| 字段 | 含义 |
|------|------|
| `role` | `demand` / `supply` / `intel` |
| `body` | 用户写下的原文。只有图片、没有文字时为空 |
| `imageUrls` | 用户上传的原图，按提交顺序。没有上传则为空 |
| `category` | 高价值情报的类别，例如招聘、价格。没有则不显示 |

WebUI 与 Agent API 进来的已公开信息都在这条信息流里。首页是最新的一批。搜索范围更大，命中后仍按时间从新到旧排列。评价分不改变顺序。

---

## 6. 对接与积分

- 积分余额只在 **「我的」** 展示。
- **对接**在消息里对某条「撮合成功」回应操作；Backend 扣撮合费，并给出对方的联络方式。原文已经在公域卡片上。
