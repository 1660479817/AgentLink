## Mark and map

- `xknot-mark.svg` — the one and only mark master, 296×296, transparent background, deep orange `#C2410C`. Page headers, favicons, home-screen icons, and share cards all rasterize from it; `knot-platform`'s page header reads its own copy at `web/public/logos/xknot-mark.svg`. There is no second version with a wordmark.
- `knot-federation-map.svg` — the federation map. Generated by `xknot.si/ops/build-federation-map.mjs`, don't hand-edit. The hub badge in the figure is `xknot.si/web/public/logos/xknot-icon-64.png` embedded inside; re-run the script after changing the mark.

## Mark geometry

The figure is made of only three things, with no hand-drawn vertices:

- **Circle**: the center ring is a `circle` with `r=23` plus `stroke-width=14`, i.e. outer radius 30, inner radius 16.
- **Standard arcs**: the four arm tips are semicircles of radius 16; the inner ends are cut by a circle centered on the figure center with radius 46, so the inner sides of two adjacent arms share the same arc.
- **Straight lines**: the two side edges of an arm, spaced 32 apart, exactly the diameter of the tip semicircle, tangent to the tip.

The four arms are one `<path>` duplicated with `rotate(45/135/225/315)`, fourfold rotational symmetry. When changing the radius, `43.128` must be recomputed as `sqrt(46² - 16²)` — it is the intersection of the arm's side edge with the inner cut circle, not a plotted coordinate.

## Horizontal lockup

`xknot-lockup.svg` is the horizontal arrangement of "mark + `Knot`", the mark used as the letter X, reading as XKnot. The same layout ships in three copies with identical geometry, differing only in color:

| File | Mark | `Knot` | Background | Used on |
|---|---|---|---|---|
| `xknot-lockup.svg` | deep orange `#C2410C` | `#050505` | transparent | default, light background |
| `xknot-lockup-mono.svg` | `#050505` | `#050505` | transparent | monochrome print, foil stamping, fax copies — must not have a second color |
| `xknot-lockup-inverse.svg` | `#FFFFFF` | `#FFFFFF` | transparent | dark background (darker than about `#444`); lay your own background underneath |

`#050505` is the platform body color, the "premium black" here; the `Knot` weight is Helvetica Neue Bold (700) — there is no heavier monospaced weight locally that wouldn't squish the letter width.

The layout is based on **cap height 160**, with all dimensions derived from it:

| Item | Value | Relative to cap height |
|---|---|---|
| Mark solid height | 168 | 1.05 × cap height, overflowing 4 above and below, balancing the diagonal weight of the four arms |
| Gap from mark to `K` | 30.4 | 0.19 × cap height, measured by ink, excluding the side bearing |
| Margins on all sides | 25.6 | 0.16 × cap height, equal on all four sides |
| Canvas | 741.48 × 219.2 | 3.38:1 |

`Knot` is the outline of Helvetica Neue Bold (weight 700, upem 1000, cap 714), already converted to paths, letter-spacing 0, rendering independent of system fonts. To change the weight, re-extract the outlines; don't just change `font-weight` — there is no font reference in the file. Changing the weight also requires no change to the mark: only replace the four glyph paths inside `<g fill="#050505">`.

These three copies differ only in color, with identical geometry: change the layout and change all three together, or they'll misalign when placed side by side.

The mark part uses the same geometry as `xknot-mark.svg` (ring `r30/r16`, arm width 32, tip `r16`, inner cut `r46`), just inlined as a copy with `id` renamed to `lockup-arm`, to avoid clashing with a master inlined on the same page. On a dark background use `xknot-lockup-inverse.svg`, don't place the default directly — orange lacks contrast on a dark background and the black text would simply vanish.

## PNG exports

`docs/png/` holds rasterized products by tier, for submission, print, instant messaging, and design-file references. Transparent background, no edge stroke; don't scale down from a larger one. All rendered directly from SVG:

| File | Size | Notes |
|---|---|---|
| `xknot-mark-1024.png` | 1024×1024 | Square mark, scaling master |
| `xknot-mark-512.png` … `-256` … `-128` | 512/256/128 | Site icons and doc figures |
| `xknot-lockup.png` / `@2x` | 1200×355 / 2400×710 | Horizontal lockup, light background |
| `xknot-lockup-mono.png` / `@2x` | same sizes | Horizontal · monochrome, for monochrome print |
| `xknot-lockup-inverse.png` / `@2x` | same sizes | Horizontal · inverse, for dark background |

Regenerate:

```sh
mkdir -p docs/png
for s in 1024 512 256 128; do
  rsvg-convert -w $s -h $s docs/xknot-mark.svg -o docs/png/xknot-mark-$s.png
done
for v in "" "-mono" "-inverse"; do
  rsvg-convert -w 1200 docs/xknot-lockup$v.svg -o docs/png/xknot-lockup$v.png
  rsvg-convert -w 2400 docs/xknot-lockup$v.svg -o docs/png/xknot-lockup$v@2x.png
done
```

The margins of the default, mono, and inverse horizontal PNGs are all 41px (1200 wide) / 82px (2400 wide), equal on all four sides; this is the 0.16 × cap-height inner padding built into the SVG, no extra cropping. To use edge-to-edge, don't crop these two; use the SVG directly and change the `viewBox`.

## Mark change process

After the master changes, regenerate by the tiers registered for each site. Don't make small icons pull the 296 original:

```sh
# Transparent-background products: page header, favicon, three icon tiers
for s in 16 32 64 128 512; do
  rsvg-convert -w $s -h $s docs/xknot-mark.svg -o /tmp/mark-$s.png
done

cp /tmp/mark-32.png  xknot.si/web/public/favicon-32.png
cp /tmp/mark-16.png  xknot.si/web/public/favicon-16.png
cp /tmp/mark-32.png  xknot.si/web/public/logos/xknot-icon-32.png
cp /tmp/mark-64.png  xknot.si/web/public/logos/xknot-icon-64.png
cp /tmp/mark-128.png xknot.si/web/public/logos/xknot-icon-128.png
cp /tmp/mark-512.png xknot.si/web/public/logos/xknot-icon.png

# Home-screen icons can't carry an alpha channel; pad a white background
rsvg-convert -w 180 -h 180 -b white docs/xknot-mark.svg -o xknot.si/web/public/apple-touch-icon.png

# The instance WebUI's page header uses the same master; knot-platform is a standalone project, copy one in
cp docs/xknot-mark.svg knot-platform/web/public/logos/xknot-mark.svg

# Share card: deep-orange background 1024, mark inverted. Generate by recoloring the master, don't hand-copy paths —
# one wrong angle and an arm lands on the axis.
sed -e 's/#C2410C/#FFFFFF/g' \
    -e 's|<g transform="translate(148 148)"|<rect width="296" height="296" fill="#C2410C"/>\n  <g transform="translate(148 148)"|' \
    docs/xknot-mark.svg > /tmp/og.svg
rsvg-convert -w 1024 -h 1024 /tmp/og.svg -o /tmp/og.png
magick /tmp/og.png -strip -quality 92 xknot.si/web/public/logos/xknot.jpg

# The badge embedded in the map is icon-64; must re-run
node xknot.si/ops/build-federation-map.mjs
```

PNGs use no palette and no color reduction, rasterized directly from vectors by tier; the figure has only one color and is small to begin with, so don't scale down from 512.

Tiers and uses are in the "Brand assets" section of [`xknot.si/docs/HUB.md`](../xknot.si/docs/HUB.md).

The instance's own implementation docs are in [`knot-platform/docs/`](../knot-platform/docs/); the federation contract and join flow are in [`xknot.si/docs/`](../xknot.si/docs/).
