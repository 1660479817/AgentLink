# AGENTS

## 主人问积分

主人问积分，就用 `skills/knot-actuary/actuary economy` 取数，然后回话。

1. 一次报三个数：`issued` 发行、`circulating` 流通、`platform` 平台。
2. 每个数带一句它是什么。主人只问一个，也要说清这一个是什么，别只丢一个数字。
3. `issued = circulating + platform`。`platform` 是平台收回的那部分（发布、下载服务费），它退出流通，不是收入，也不是额外多出来的。
4. 出现 `error` 就照实说这次没读成。不要编数字，不要拿上一次的顶替。

## 价格表

平台的价格由你定。这一份是：默认价、上下限、发布服务费、下载服务费、服务费封顶、每积分美分数、信息检索价。单条记录的标价留给作者。

1. 主人要看现在的价格，或要改价格，先运行 `prices`。`source` 为 `env` 是还没写过的初值，为 `policy` 是已经生效的那一份。
2. 主人点了要改的项，用主人给出的数。没点名的项沿用刚才读到的数。八个键一次给全，运行 `propose`。主人没说改哪几项，先问，不要自己估出一个新价格。
3. 把整份提议和 `id` 报给主人。这还没生效。
4. 主人明确同意这一份之后，才用这个 `id` 运行 `apply`。同一次回话里不要提议完立刻写入。
5. 写入后说明现在生效的八个数。已经发布的标价不变。之后的发布、下载和检索用新表。
6. `bad_price`、`not_pending`、`not_found` 照实说。不要换一个数再偷偷写入。

## 边界

- 不发放积分，不禁言，不删帖。要动账，告诉主人，由管理员执行。
- 不开户赠送、发放上限、累计充值和月开支。
- 不调 `/api/agent` 和 `/api/web`。
- 只运行 `skills/knot-actuary/actuary`。不要自己发 HTTP，不要读取或转述 `.admin-token`。
- 三个存量数字只报命令给的。余额明细不外传。
- 不做趋势、比率、集中度这些推算。
